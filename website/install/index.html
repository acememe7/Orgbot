Install OrgBots from its signed APT archive.

Download the installer, read it, then run it in Bash. It checks the signing key fingerprint before adding the repository and installing the package.

Current release: OrgBots 2.2.0 is available in the signed APT archive.

Review the live room evidence.

Before you start

These instructions support Ubuntu 24.04 on amd64. You need an internet connection and permission to use sudo. Install the stated prerequisites if they are missing:

sudo apt update
sudo apt install curl ca-certificates gnupg coreutils

The installer does not automatically install missing prerequisites. APT shows its normal package confirmation prompt before installation.

Download, inspect, and run

Keep the commands separate. First download the script:

curl -fL https://raw.githubusercontent.com/acememe7/Orgbot/main/scripts/install-orgbots.sh -o install-orgbots.sh

Read the downloaded file and confirm its source before you run it:

less install-orgbots.sh

Then run it as your user. It requests elevated access only for system package configuration:

bash install-orgbots.sh
The installer pins signing-key fingerprint 81445722C3B9265312C12039F831B11611E6D198 and scopes APT trust to the OrgBots archive. It does not pipe downloaded content directly into a privileged shell.

Open OrgBots and connect a provider

Launch OrgBots from the desktop menu or run orgbots in a terminal. In Connections & tools, add an API provider key or use a supported CLI sign-in already set up on this computer. API credentials and provider subscriptions are separate billing arrangements. Connect the Ollama Cloud API if you use Ollama; OrgBots does not include a local Ollama GUI.

Upgrade OrgBots

After the one-time repository setup, use APT to refresh package information and install updates:

sudo apt update
sudo apt install orgbots

The current package is OrgBots 2.2.0. The APT archive is a third-party repository hosted at the OrgBots GitHub Pages archive, separate from Ubuntu's built-in archive.

Remove OrgBots

Remove the application through the package manager:

sudo apt remove orgbots

This does not automatically remove the repository configuration or your user data. You can leave the source configured for future installation or remove its source and keyring files after inspecting them.

Workspace protection and file recovery

OrgBots does not format or configure disks. From 2.0.1, recoverable files default to ~/.local/share/orgbots/trash, or $XDG_DATA_HOME/orgbots/trash when that variable is set. Open Connections & tools, then File recovery to choose another folder. Existing HDD users keep their selected recovery folder; if that storage is offline or fails verification, protected integration stops until it is available.

Applying an agent’s project-file removals requires your approval of the exact deletion list, and originals move to recoverable trash. Remote tool effects are outside this local recovery boundary. An optional daily systemd cleanup timer can be installed and enabled separately; it only removes entries after seven full days. The package does not enable this timer automatically. Older package-only installations ask you to select a recovery folder explicitly after upgrading. A folder containing recovery entries cannot be switched until those entries are resolved.

Local workspace protection does not provide complete network or credential isolation. Private portable backups are unencrypted and limited to 64 MiB. Treat secrets pasted into agent history as sensitive. Read the workspace safety guide before connecting providers.
