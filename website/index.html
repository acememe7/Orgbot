Keep each agent’s work reviewable.

Agents use isolated project copies. OrgBots compares each copy with the project before integration and surfaces conflicts and deletions for owner review.

When an agent changes the same file as the owner, integration stops and shows the conflict. Replacing or removing an existing file requires a writable ext4 drive mounted at /mnt/hdd; originals go to /mnt/hdd/OrgBots Trash.

  • Separate copies preserve the project while agents work.
  • Conflict review keeps overlapping edits out of the integration step.
  • Deletion approval names the exact files before they move to Trash.

Follow the work and its usage.

Rooms preserve the work session. Usage records separate input, output, cache reads, and cache writes by provider and agent.

Use the room history to pick up work, answer an agent’s question, and inspect what each provider contributed. When the provider returns enough data, OrgBots records token categories and API cost estimates.

  • Subscription usage stays distinct from actual API charges.
  • Missing usage or pricing remains unknown.
  • Local CLI subscriptions and provider API keys are managed separately.

Keep a team session in one place.

Rooms carry questions, notifications, attachments, previews, and background work alongside each project. Bring your installed tools and review each permission request.

The specialist preset uses Astra for code and security coordination and review, and Julian (Opus) for design and architecture coordination. Choose the available models and roles for each room. Codex, Claude, and Grok CLI use their installed Linux accounts. API providers and an Ollama endpoint can be configured separately.

  • Project context: work with files, Git, MCP tools, and skills available through installed tools, subject to their permissions.
  • Continuity: return to the room history, open questions, notifications, and ongoing work.
  • Portable backups: private backups are unencrypted and capped at 64 MiB.
