You decide what the bots can touch.

Anything with lasting effect waits for your answer, and the answers that matter ask you to confirm.

  • Servers by permission. Bots have no server key until you allow one for a specific task. It disappears when that task is blocked, held, in review or done, and reviewers never get it.
  • Stale work retired with one tap. A coordinator proposes retiring an obsolete task and you confirm. In the live room this ended wake-ups that had been costing turns.
  • Pause without losing work. Pausing lets running turns finish first, so an update loses nothing.

Keep each agent’s work reviewable.

Agents use isolated project copies. OrgBots compares each copy with the project before integration and surfaces conflicts and deletions for owner review.

When an agent's copy and your project change the same file differently, integration stops for your review. File removals wait for your approval and go to recoverable trash on the disk you choose. Copies left by bots no longer in a room are cleaned up on their own; in the live room that freed 41.7 GB.

  • Separate copies preserve the project while agents work.
  • Conflict review blocks differing edits to the same path.
  • Deletion approval names the exact files before they move to Trash.

Follow the work and its usage.

Rooms preserve the work session. Usage records separate input, output, cache reads, and cache writes by provider and agent.

Use the room history to pick up work, answer an agent’s question, and inspect what each provider contributed. When the provider returns enough data, OrgBots records token categories and API cost estimates.

  • Subscription usage stays distinct from actual API charges.
  • Missing usage or pricing remains unknown.
  • Local CLI subscriptions and provider API keys are managed separately.

Keep a team session in one place.

Rooms carry questions, notifications, attachments, previews, and background work alongside each project. Each agent keeps its own provider session with its role and room goal in the standing prompt.

The specialist preset uses Astra for code and security coordination and review, and Julian (Opus) for design and architecture coordination. Choose the available models and roles for each room. Codex, Claude, and Grok CLI use their installed Linux accounts. DeepSeek API and the Ollama Cloud API can be configured separately. OrgBots does not include a local Ollama GUI.

  • Fresh handoffs: each turn refreshes task state, new room messages, waiting handoffs, and review findings. When Astra records findings on Julian’s task, Julian sees them in his next digest. Older board snapshots are replaced when stale.
  • Artifacts on demand: the room lists deliverables by ID; a worker reads the full artifact when it is relevant.
  • Team checks: workers self-check, Quinn handles QA and reproduction, and an independent reviewer checks combined changes. This is the preset’s intended agent workflow, not an automatic test hook.
